# デシイリ SaaS：バックアップから戻す手順

## バックアップのしくみ

- 毎晩 3:00（日本時間）に、定時の仕事 `/deshiiri/api/cron/nightly` がデータベースの中身を JSON にして gzip し、共有ドライブ「デシイリ原本」の「バックアップ」フォルダに保存します（プレビューのテスト用データは「バックアップ（プレビュー）」に分けて保存します）。
- ファイル名は `deshiiri-backup_YYYY-MM-DD_HHMM.json.gz`（日本時間）。30 個を残し、古いものはドライブのゴミ箱へ移します（ゴミ箱は 30 日で自動的に空になります）。
- 管理画面の「運用」から、いつでも手で保存できます（「今すぐバックアップする」）。
- 入っている表：craftspeople, invite_codes, works, work_photos, visit_requests, push_log, batch_jobs, events。line_events（LINE の二重処理よけの控え）は入れていません。
- **写真そのものは入っていません。** 写真の原本はドライブの職人ごとのフォルダに、表示用は R2 にあります。バックアップに入っているのは、その置き場所（r2_key・drive_file_id）です。
- 若者の連絡先も入っています。ドライブのバックアップフォルダは編集部だけが見られるようにしてください。1年たって消した連絡先も、それより前のバックアップには最大 30 日残ります。

## 戻すとき

### 1. どこに戻すか決める

- **ふだんは、新しい Neon のブランチに戻します。** 本番のデータベースに直接戻すと、いまあるデータと混ざります。Neon の画面でブランチを作ると、新しい接続文字列が出ます。
- 消えた行だけを戻したいときは、本番に戻しても大丈夫です。同じ ID の行は上書きせずに飛ばします。

### 2. バックアップを手元に落とす

共有ドライブ「デシイリ原本/バックアップ」から、戻したい日のファイルをダウンロードします。

### 3. 表を作る

戻し先が空のデータベースなら、先に表を作ります。

```bash
DATABASE_URL='（戻し先の接続文字列）' npx drizzle-kit migrate
```

### 4. 中身を確かめる（書き込まない）

```bash
node scripts/deshiiri/restore.mjs ./deshiiri-backup_2026-11-13_0300.json.gz --dry-run
```

### 5. 戻す

```bash
DATABASE_URL='（戻し先の接続文字列）' node scripts/deshiiri/restore.mjs ./deshiiri-backup_2026-11-13_0300.json.gz
```

表ごとに「何行のうち何行を入れたか」が出ます。

### 6. サイトを戻し先に向ける（ブランチに戻した場合）

Vercel の環境変数 `DATABASE_URL` を、戻し先の接続文字列に変えて、もう一度デプロイします。

### 7. 確かめる

- 管理画面の「接続を確かめる」がすべて OK になる。
- 職人ページ・職種一覧に、公開済みの仕事の一日が出る。
- 「見学の進行」に申し込みが並ぶ。

## 気をつけること

- 接続文字列はパスワードを含みます。チャットやメール、このリポジトリに貼らないでください。手で打つときは、終わったらターミナルの履歴から消してください。
- ダウンロードしたバックアップには若者の連絡先が入っています。戻し終わったら手元のファイルは消してください。
